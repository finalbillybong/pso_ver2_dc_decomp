## Method

Batches 244–249 come from candidate units that no earlier candidate covered. The boundary review disclosed in batch 243 found them; this is batch 244, and the batches split the units by address. The draft generator did not change: every draft is from the generator used for batch 242's pool cycle, drafted in 11 modes at the reviewed range. All are unedited generated drafts.

**How the units were found.** About 277 KB of decoded game code lay in no admitted function and no candidate range. The review found four causes:
- **Unrecorded entries (60%).** No candidate started there:
  - most of these functions are reached only through a vtable or function-pointer table in data;
  - some contain a jump table, so the earlier miners dropped or cut them;
  - the rest are referenced by a call or literal but were discarded by the earlier miners' next-start rule.
- **Dropped candidates (33%).** Candidates had been removed from the pool, most with a correct range.
- **Tails cut off (2.5%).** Ranges stopped short at a jump table, a mid-function literal pool or an early `rts`.
- **Held back (2.5%).** Code owned by blocked or history-held targets, left as it is.

**Entry and range rules.**
- **Entries.** Each entry needs positive evidence:
  - a `bsr` target;
  - a pool literal used by `jsr` or by a tail `jmp`;
  - a function pointer loaded and not called;
  - or a word in a vtable or function-pointer table in data.

  Jump-table words are case-arm addresses and are never used as entries. The code before each entry must end in a delay slot, a literal pool or filler.
- **Ranges.** The range comes from a walk that follows every branch and jump-table arm. It ends at the last literal-pool or table word the code references. It is rounded to 4 bytes only when the next halfword is filler.
- **Rejections.** A unit is rejected if its walk branches before the entry, falls into another entry, contains unexplained words, or overlaps an admitted function.
- **Check against admitted functions.** The rule reproduces the manifest size of all 7,803 admitted game functions.

Drafts were accepted only when exact over the full reviewed range. The history guard refused no attempt in these batches. Previously blocked targets stay blocked, and the three drafts held back in batch 224 remain held back.

Before admission, the boundaries of every unit in this batch were checked:
- each entry follows a literal pool (200) or a function end (33);
- no unit overlaps an admitted function or another unit;
- no branch from outside a unit lands in it;
- every entry is 4-aligned.

## Observed techniques

- Functions reached only through a vtable or function-pointer table are the largest group of code that had no candidate. A walk from the data tables finds their entries.
- Jump-table words in a literal pool are case-arm addresses. Treating them as entries split switch functions into fragments.
