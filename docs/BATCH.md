## Method

Batch 213 comes from a second candidate survey. It covers game code below the SDK region that remained outside every candidate range after batches 207 to 212, about 54 KB in 768 runs. A scratch script took each run's first instruction as a function start when:
- the start is 4-aligned;
- it directly follows a literal pool or alignment padding;
- the code before that pool ends a function in the delay slot of `rts`, `jmp` or `bra`;
- no branch from outside the candidate lands on the entry or inside it, except a `bsr` to the entry.

Bodies are the reachable code, and ranges run to the next start or covered byte. A candidate is dropped if code it does not reach is left over in its range.

The survey found 727 candidates. They were drafted with the batch 212 generator, unchanged.

Before admission, the boundaries of every exact unit were checked again:
- each entry follows a literal pool;
- no unit overlaps an admitted function or another unit;
- no branch from outside any unit lands on its entry or inside it;
- every entry is 4-aligned.

Each entry is also referenced by an aligned pointer word in the image, outside the game-code range. The batch 207 survey scanned only words inside the game-code range for references. These references come from the data region, which is consistent with virtual tables and callback tables.

Calibration: 22/37 on batch 191 and 31/55 on batch 190, unchanged.

## Measured attempts

390 recorded attempts on 390 targets, all hypotheses and all exact. 390 units / 390 functions / 22,904 bytes were admitted after two independent reproductions each. Nine are functions of 8 bytes or less.

All are unedited generated drafts. A further 40 drafts were exact in scratch but not as recorded trials, and are not admitted.

Disclosure:
- Every admitted function was first found exact in a scratch comparison, as logged under `drafttest/`.
- No admitted source was edited by hand.
- No new hand probes were made for this batch.
- No declaration orders were searched.
- History-guarded targets stay blocked and were not forced.

Signatures are provisional. Parameter and return types come from the instruction shape and literal use; they are not confirmed against callers. Identifiers are mechanical.

## Observed techniques

- Pointer words in the data region are the remaining entry source. Many functions are reached only through tables there, not through a literal pool in code.
