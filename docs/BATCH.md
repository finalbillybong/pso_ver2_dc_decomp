## Method

Candidates came from a call-readiness scan of the existing Ghidra function export:
unadmitted game-code entries (below `0x8c285000`; nothing above `0x8c28455c` has
matched) whose direct calls all target admitted functions, with literal pools that
end at the next reviewed entry. Masked instruction shapes grouped them into
families; one exact representative was trialled before its siblings, which differ
only in constants. REA 6.4.0 (Ghidra 12.1.4, SH-4 language override) supplied
decompilation and reference checks during review; it does not participate in
compilation or comparison.

## Measured attempts

215 recorded attempts on 178 targets: 214 hypotheses and 1 correction (a merged
group source that declared one struct twice). One attempt was a compile error.
149 attempts were exact. 142 new units / 150 functions / 5,276 bytes were admitted,
together with the carried 44-byte `slide_and_dispatch_contact` from the bounded
pilot, after two independent reproductions each.

## Observed techniques

- Externally bound globals (`extern` data symbols in the unit's `symbols`) reproduce
  address loads scheduled before stores; address-cast globals did not. This is the
  data analogue of CW04.
- Explicit shifted byte offsets reproduce `shll`/`shll2` index scaling where array
  subscripts emitted `mul.l` (CW10), including struct-array and pointer-table cases.
- Struct fields at large offsets reproduce indexed `@(r0,rN)` accesses; `char *`
  arithmetic emitted a separate `add`.
- Named integer predicates reproduce materialized `movt`/`tst` tests (CW07).
- Functions that were instruction-exact but two alignment bytes short matched when
  compiled with their real exact successor in one unit (CW06): range lookups, member
  selectors, bounded stores and a clamp/split pair.
