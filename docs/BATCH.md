## Method

Batch 261 combines two generator cycles, hand-finished near misses and the first units admitted under a new padding rule.

**Generator rules.** Two scratch research passes turned recurring hand fixes into generator rules, each behind its own flag:
- The first added 11 rules, among them: a halfword member whose loaded value is extended twice is declared `volatile unsigned short` (CW20); a local placed at a stale insertion point no longer reads a pointer before it is allocated; leftover argument registers beyond an admitted callee's parameters are dropped; a member read whose load follows the next statement's computation is written after it; float frame members passed by address keep their stores; a quotient local is reused instead of a repeated division; a void if/return pair whose last return keeps an unfilled branch slot becomes if/else; signed narrow members stored back unchanged become `short` locals; and float compares are written in load order.
- The second added 24, among them: a post-decrement inside a `> 0` test; an inline `-1.0f / (x + k)` constant; stack reads that account for a pushed stack argument (restoring dropped frame stores); dropping float arguments a callee's definition does not take; one-time int-to-float conversions and parameters used directly; split tables read through one base literal; explicit `case k: break;` labels in sparse switch trees; do-while tests that read through the stepped pointer; shared shifted indexes and conditions assigned in the first test; and a virtual call's receiver loaded once.

Both passes left calibration at or above its previous level (34 / 44 / 8 after the first pass, up from 32 / 44 / 8), and their per-function, per-mode regressions over every admitted plan (190, 191, 211–260), the jump-table set, earlier agents' result lists and earlier batch files lost no exact draft. No rule chooses a declaration order or produces the `(v >= 0 ? v : v)` idiom.

**Redraft.** The 3,383 remaining candidates were redrafted in the 11 regular generator modes after the first pass. It found 122 exact drafts; one was a new full-range exact draft. The other 121 were exact for all but the last two bytes of their unit.

**Padding rule.** The project now admits a unit whose compiled code matches exactly and whose only remaining range bytes are one trailing zero halfword that aligns the next routine to four bytes; the unit is admitted at its code size (range minus two), and the halfword stays unassigned. All 121 such drafts met it: in each, the reference has a single `.word 0x0000` after the final instruction and the following routine starts on a four-byte boundary. 117 were admitted; the history guard refused 4 (`0x8c03bdb0`, `0x8c0a7608`, `0x8c0b49b0`, `0x8c1a1984`), which were not forced. Three hand-finished sources were admitted the same way (see below). The batch-193 boundary rule is unchanged.

**Hand-finished near misses.** Five scratch passes took:
- 40 large never-probed targets (600–3,008 bytes, sorted by differing lines per byte) (0 exact; 4 exact sources held back, see below);
- 18 targets whose draft had improved after the generator passes (1 exact);
- 40 further large never-probed targets (1 exact, plus 4 siblings exact for their code; 3 admitted under the padding rule, 1 refused by the history guard);
- 40 more never-probed targets of 500 bytes and up (1 exact);
- the last 35 never-probed targets within 400 differing lines (0 exact; two are library-style serial-port routines).

They used the rules of batches 241–260:
- at most ten distinct hypotheses per target, counting earlier probes, with identical compiler outputs counted once;
- ordinary C or C++ only, with the pinned compiler and flags;
- full-range exact only (now including the padding rule);
- no declaration-order search.

All exact sources were trialled; all but those refused by the history guard are admitted.

**Declaration-order comparisons.** The passes made labelled comparisons, at most one per target. Held back and not trialled, because declaration placement decided the match: `0x8c0ac934`, `0x8c0b11f4`, `0x8c0b4d34`, `0x8c106a6c`, `0x8c139fc4`, `0x8c1b4e40`, `0x8c1e0abc`, `0x8c1cc6e0`. Comparisons where the other placement was also exact: `0x8c211314` and `0x8c1c9730` (both admitted). Further comparisons on parked targets did not make them exact.

**Measurements that changed nothing.**
- A fixed innermost-scope declaration rule was tested against every admitted source with a criterion set before compiling. Every rewrite that changed the compiled output broke the match (35 of 35); the rule was rejected and nothing is admitted under it.
- The only installed compiler build accepts optimisation level, speed/space and inlining settings; scheduling, peephole and register colouring cannot be switched. Compiling at `-O3` makes about 81 near-miss drafts exact without source changes, but 11.4% of admitted functions match only at the pinned `-O2`, the two kinds are interleaved function by function, and a pre-registered test found no rule computed from the listing that predicts which level a function needs. Nothing compiled at another level is admitted.

Previously blocked targets stay blocked, and the three drafts held back in batch 224 remain held back.

Before admission, the boundaries of every unit were checked:
- each entry follows a literal pool (104) or a function end (20);
- no unit overlaps an admitted function or another unit;
- no branch from outside a unit lands in it;
- every entry is 4-aligned.

## Observed techniques

- A post-decrement inside a `> 0` test fills the branch delay slot.
- Repeated tag switches inside a goto tangle were inline helper functions taking the object and a mode.
- A table lookup written as a macro with a literal index avoids the stray `add #0` that an inline function with an index parameter leaves.
- Many small routines end with a zero halfword that aligns the next routine; their code matches exactly at its own size.

## Parked and unresolved

- **Register allocation and scheduling** that this compiler build produces at `-O3` but not at the pinned `-O2` account for many near misses; no per-function rule selects between them.
- **The angle conversion** that reloads one float register for each constant, **large-offset field addresses**, and **float argument order** for some vector callees recur without a source form.
- **Declaration order** decides register assignment and frame layout in many remaining near misses. Such sources are held back, not admitted.
- **Argument-register order around a call's delay slot**, **in-place `extu.w`** and frame-pointer helpers remain out of scope.

Code-only completion and total function count remain unknown.
