## Method

Batch 207 is a generator cycle, plus a new candidate survey. The draft generator gained:
- **Loops:** a `bra` back edge with exits only through `break` or a return is written `for (;;)`. Writes that happen only on the exit path are moved after the loop. A preheader computation that the compiler hoisted is written before the loop. A post-tested loop whose counter is assigned inside the body is written as a `do`/`while` with the assignment in place.
- **Variadic calls:** a call whose arguments are all on the stack gets the prototype `(T, ...)`. That is how this compiler passes variadic arguments.
- **Pointer arithmetic:** offsets on a `char *` local are written as pointer arithmetic, and negative offsets are formatted as subtraction. Shifts and relational compares on such a local treat it as a pointer.
- **Switch defaults:** `case k: default:` is used when a case shares the default body.
- **Function-pointer arguments:** call arguments are cast to the declared function-pointer type.
- **Compiler jump tables:**
  - the generator now runs the instructions between the subject computation and the bounds check, such as a register copy, so the subject is known;
  - an unadmitted callee's argument count is read from the argument registers it uses before writing them, in a straight-line scan from its entry;
  - float parameters no longer count against the integer argument registers;
  - a prototype first seen at a call that ignores the return value is upgraded when a later call uses it.

Candidate survey: the remaining game code below the SDK region was not covered by any earlier candidate list. A scratch script mined function entries from it:
- **Entries:** aligned literal words that point into uncovered code, plus code that resumes after a function's literal pool.
- **Bodies:** the code reachable from each entry.
- **Ranges:** each runs to the next known start, capped at 2,048 bytes.

This found 3,734 new candidates. Before admission, every exact unit's boundaries were checked:
- every entry follows a literal pool, alignment padding, or the delay slot of a function-ending `rts`, `bra` or `jmp`;
- no branch from outside a unit lands inside it, and the only outside branches to an entry are three `bsr` calls;
- no entry is referenced from a jump table.

Scratch tooling changes:
- Probe entry detection now accepts `extern "C"` definitions. This lets C++ units with jump tables link with the native linker.
- `drafteval.py` can select the generator script through an environment variable. This was used to test the jump-table changes in a separate copy before merging them.

Calibration: 20/37 on batch 191 and 31/55 on batch 190, unchanged after every rule. The 13 admitted jump-table functions were redrafted as a further check, and 8 are exact from the generator alone.

## Measured attempts

The exact drafts from this cycle are admitted over batches 207 to 211 in address order. Each function has one recorded attempt, a hypothesis that was exact.

This batch admits 395 units / 395 functions / 19,012 bytes, each after two independent reproductions:
- 382 come from the new candidate survey;
- 7 come from the loop and variadic rules;
- 4 are compiler jump-table switches recovered by the jump-table changes;
- 2 come from earlier generator rules.

All are unedited generated drafts. Many of the new candidates are small: functions of 8 bytes or less make up 520 of the 1,727 functions across batches 207 to 211. Each of them is referenced by a pointer in the image.

## Observed techniques

- The earlier candidate lists missed a large set of ordinary game functions. Literal references into uncovered code are a reliable entry source, because the compiler loads every call target and function pointer through a literal pool.
- A `bra` back edge whose only exits are `break` and return statements corresponds to `for (;;)`, with exit-only writes after the loop.

## Parked and unresolved

- Mid-entry loops: drafts are structured but not exact, because the source layout the compiler expects is unknown.
- Remaining jump-table drafts fail to compile mostly because of unrelated field typing: frame fields, illegal operand casts, float casts, and parameters that are not detected.
- The unparked items from batch 206 (`extu.w`, argument-register order, `0xffff` returns) are unchanged.

Code-only completion and total function count remain unknown.
